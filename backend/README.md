# DevicePulse Laravel Backend

This repository contains the Laravel REST API backend for the DevicePulse mobile application. It covers secure device enrollment, GPS upload and history retrieval, and estimated data-usage reporting.

## Local setup

1. Install PHP 8.3+ and Composer.
2. Copy the environment file:
   ```bash
   cp .env.example .env
   ```
3. Generate the application key:
   ```bash
   php artisan key:generate
   ```
4. Configure MySQL in `.env`:
   ```env
   DB_CONNECTION=mysql
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=devicepulse
   DB_USERNAME=devicepulse
   DB_PASSWORD=change-me
   DEVICEPULSE_ENROLLMENT_CODE=your-enrollment-code
   ```
5. Create the database and run migrations:
   ```bash
   php artisan migrate
   ```
6. Start the backend:
   ```bash
   php artisan serve --host=0.0.0.0 --port=8000
   ```

## MySQL setup

```sql
CREATE DATABASE devicepulse CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'devicepulse'@'localhost' IDENTIFIED BY 'change-me';
GRANT ALL PRIVILEGES ON devicepulse.* TO 'devicepulse'@'localhost';
FLUSH PRIVILEGES;
```

## API overview

Base URL: `http://localhost:8000/api`

### Device registration

`POST /api/devices/register`

Request:
```json
{
  "deviceId": "unique-device-id",
  "deviceName": "Android Phone",
  "platform": "android",
  "enrollmentCode": "your-enrollment-code"
}
```

Response:
```json
{
  "accessToken": "issued-bearer-token"
}
```

### GPS upload

`POST /api/locations`

Headers:
- `Authorization: Bearer <token>`
- `Idempotency-Key: <updateId>`

Request:
```json
{
  "updateId": "7d5d0d1a-1a8b-4d97-9a3d-c3c4d2be82d4",
  "deviceId": "unique-device-id",
  "timestamp": "2026-10-11T08:00:00Z",
  "latitude": 10.123456,
  "longitude": 124.123456,
  "accuracy": 8.5,
  "altitude": 12.25,
  "speed": 1.4,
  "heading": 270,
  "coordinatePayloadBytes": 150
}
```

The GPS measurements are optional and may be `null` when Android has no value. Apply all migrations with `php artisan migrate` to add their nullable columns.

For an Android phone to reach a Laravel server running on the laptop, start Laravel with `php artisan serve --host=0.0.0.0 --port=8000`, put both devices on the same trusted Wi-Fi, and set the Expo app's `EXPO_PUBLIC_API_BASE_URL` to `http://<laptop-wifi-ip>:8000/api`. Do not use `localhost` in the phone's URL.

### Data usage upload

`POST /api/data-usage`

Headers:
- `Authorization: Bearer <token>`
- `Idempotency-Key: <updateId>:usage`

Request:
```json
{
  "updateId": "7d5d0d1a-1a8b-4d97-9a3d-c3c4d2be82d4",
  "deviceId": "unique-device-id",
  "timestamp": "2026-10-11T08:00:00Z",
  "requestBodyBytes": 120,
  "estimatedRequestHeaderBytes": 60,
  "responseBodyBytes": 400,
  "estimatedResponseHeaderBytes": 80,
  "estimatedUploadBytes": 180,
  "estimatedDownloadBytes": 480,
  "estimatedTotalBytes": 660
}
```

### Retrieval endpoints

- `GET /api/devices/{deviceId}/locations/latest`
- `GET /api/devices/{deviceId}/locations?from=...&to=...&page=1&limit=25`
- `GET /api/devices/{deviceId}/data-usage/summary`

## Security notes

- Device enrollment requires a server-side enrollment code when configured.
- Tokens are hashed before storage.
- The app must never send a raw device ID as proof of identity.
- Each device can only access its own data.
- Idempotency keys prevent duplicate submissions on retry.
- HTTPS is required in production.

## Data usage methodology

The backend stores estimated upload and download figures based on the mobile app's request/response byte calculations. This is not exact cellular network accounting and does not include all traffic generated by the device or OS.

## Deployment guidance

- Run behind HTTPS with a reverse proxy or load balancer.
- Configure `APP_ENV=production` and `APP_DEBUG=false`.
- Restrict database access and rotate `DEVICEPULSE_ENROLLMENT_CODE` regularly.
- Use a real DB credential store rather than committing secrets.
